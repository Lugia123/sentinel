## R1 A股新闻源普查(2026-07-14)

**假设**:仅用免费源(akshare + 公开 HTTP)即可覆盖 L1/L2 的 80% 需求,PIT 可行。

**做法**:逐源探测可用性/延迟/字段/时间戳/历史回补能力(每源 25s 超时,避免反爬源卡死)。

**数据**(实测,scratchpad/probe_news.py + probe2.py):

| 源 | akshare 函数 | 量 | 延迟 | 时间戳 | 历史回补 | 用途 | 层 |
|----|------|----|----|----|----|----|----|
| 东财全球快讯 | `stock_info_global_em` | 200条 | 0.1s | 发布时间(当天实时) | ✗ 只最近 | 宏观快讯主力 | L1 世界/国内 |
| 新浪全球财经 | `stock_info_global_sina` | 20条 | 0.2s | 时间(实时) | ✗ | 实时补充 | L1 |
| 同花顺全球 | `stock_info_global_ths` | 20条 | 0.2s | 发布时间 | ✗ | 补充 | L1 |
| 央视新闻联播 | `news_cctv(date)` | 14条/天 | 1.3s | date | ✓ **按日期回补** | 国内大事权威 | L1 |
| 财新主新闻 | `stock_news_main_cx` | 100条 | 0.4s | ✗(需从 url 解析) | ✗ | 深度财经 | L1/L2 |
| 个股新闻 | `stock_news_em(symbol)` | 10条/股 | 0.1s | 发布时间 + **关键词列** | ✗ ~2周 | 个股关联核心 | Phase C |
| **个股公告** | `stock_individual_notice_report(security)` | **1500条/股** | ~2s | 公告日期 + **公告类型** | ✓ **14年(2012→今)** | 关联+回测核心 | Phase C + L3 |
| 财报发布日历 | `news_report_time_baidu(date)` | 12条 | 快 | 发布时间 | date 参数 | 事件日历 | R7 |
| 财联社电报 | `stock_info_global_cls` | — | **超时(反爬)** | — | — | 弃用 | — |
| 经济数据日历 | `news_economic_baidu` | — | **403** | — | — | 暂不可用 | — |
| GDELT 世界大事 | DOC 2.0 HTTP API | — | 返回非 JSON(限频?) | — | ✓ | 需二次验证(可被东财全球快讯替代) | L1 备选 |

**结论**:
1. ✅ **假设成立**:免费源足够撑起 L1/L2。宏观/大事有东财全球快讯(量大快)+ 央视(权威可回补)+ 新浪/同花顺(实时补充)+ 财新(深度)。
2. 🏆 **个股公告接口是金矿**:14 年历史 + 结构化「公告类型」+ PIT 公告日期。这是**唯一有深度历史的新闻类数据**,一石二鸟——Phase C 个股关联最可靠来源(公司自己发的),又是 L3 回测的历史底料(接续 SAFNA-A 唯一成活的 rev+PEAD 事件腿)。
3. ⚠️ **冷启动是核心约束**:除个股公告和央视外,所有源只给「最近 N 条」,不支持深度回补。
   → **L1/L2 立即可用**(只需最近的);**L3 回测的新闻历史必须靠自己从采集日起持续积累**(除公告外)。这决定了采集管道要尽早上线跑起来攒数据。
4. 🎯 **PIT 分层结论**:实时快讯类(东财/新浪/同花顺)延迟 <1min、时间戳可信 → 满足 R2 的 L3 准入;央视/公告有明确日期 → PIT 干净。财联社、经济日历弃用。

**产出源清单(采集管道 R3 的输入)**:
- 宏观/大事:`stock_info_global_em`(主)+ `news_cctv`(日报权威 + 可回补)+ `stock_news_main_cx`(深度)
- 个股:`stock_news_em`(近期新闻带关键词)+ `stock_individual_notice_report`(公告,深历史)
- 日历:`news_report_time_baidu`(财报发布)

**下一步(R2)**:PIT 时间戳审计——抽样核对各源「发布时间 vs 实际可抓到时间」,标定每源的可用延迟;确认实时快讯类的时间戳能否用于事后 L3 回测。同时评估央视/公告的历史回补深度上限。

## R2 PIT 时间戳审计(2026-07-14)

**假设**:各源的时间戳可信,能用于事后 L3 回测(无前视)。

**做法**:①测实时快讯的端到端延迟(发布时间 vs 本地抓取时刻)+ 时间戳单调性;②测深历史源(央视/公告)的回补深度与 PIT 洁净度;③存快照 A(snap_A.txt)留待下轮对比时间戳是否被事后回填。

**数据**:
- **实时快讯延迟**:东财 4.5min / 新浪 1.4min / 同花顺 3.4min。时间戳**全部可解析、严格倒序单调**、北京时间。
- **央视回补**:2020/2023/2025 各年都能精确取当天(16-18条/天),PIT 完美(按日期取,不含未来)。
- **公告回补**:茅台 1067 条覆盖 **2001→2026(25 年)**,按公告日精确,PIT 完美。
- **公告类型是结构化字段**(跨 5 股汇总 top 类型见下),可直接做规则粗筛。

**结论**:
1. ✅ **PIT 分两档**:
   - **深历史源(央视 + 公告)= PIT 完美**:按日期/公告日精确定位,无前视,可直接进 L3 回测。
   - **实时快讯(东财/新浪/同花顺)**:延迟 <5min,对**日频信号无前视风险**(5min vs EOD 收盘可忽略;规则=publish_time<14:57 当日可知,之后次日可知)。残留风险=时间戳事后篡改,已存快照 A 待下轮核对(低概率)。
2. 🎯 **公告类型白名单(两级漏斗规则粗筛的核心产物)**:
   - **高信号(进白名单)**:分配预案/分配方案实施·回购进展·股权激励·关联交易·**股份质押冻结(风险)**·对外担保·月度经营·年报/半年报/季报·限售股解禁·股本变动·高管变动
   - **噪声(剔除或低权重)**:其他/股票(无法分类)、专项说明/独立意见、保荐核查、法律意见书、独董述职/声明、议事规则/管理制度、审计报告、章程修订、内控报告
   - **需靠标题关键词补识别**(未在 top 类型出现,但高价值):中标/重大合同、资产重组、诉讼仲裁、监管处罚/问询函 → R9 实体链接时用标题正则补齐
3. **冷启动再确认**:实时快讯无历史 → L3 用得上历史的只有公告(25年)+ 央视(可回补)+ 已有 alt 数据(analyst/yjyg)。这三者是 L3 底料;情绪/舆情类信号的历史只能从采集日起攒。

**下一步(R3)**:建采集管道原型 news_collector.py + PG 表(news_items / stock_announcements),接入 R1 源清单,去重落库,本地跑通一次;规则粗筛应用 R2 白名单。

## R3 采集管道原型(2026-07-14/15)

**假设**:免费源可无人工干预连续跑通,去重可靠,规则粗筛(公告白名单)能自动区分信号/噪声。

**做法**:建 PG 表(迁移 0012:news_items 通用流 + stock_announcements 深历史)+ news_collector.py
(asyncpg,与 backfill.py 一致);接入 R1 源;fingerprint 去重;公告按 R2 白名单标 is_signal。
本地建表跑通:--macro / --stocks / --cctv-date / --ann-backfill 四种模式。

**数据**(本地实跑):
- news_items 286 条:em_global 200 / sina 22 / ths 20 / cctv 14 / 个股新闻 30(带关键词)。
- stock_announcements 107 条(3 股近 90 天),白名单命中 37 条(is_signal)。
- **去重验证**:macro 第二次跑只新增 2 条(真新增),fingerprint 去重生效。
- **时区验证**:央视 published_at 存 11:00 UTC = 北京 19:00 播出,正确。

**结论**:
1. ✅ 管道跑通,四模式可用;去重、时区、白名单标注都正确。
2. 🔁 **白名单需抽查迭代**(R3 现场发现并修复):类型白名单能抓结构化公告,但高价值新闻常被归入
   「其他」类型 → 靠标题正则补。抽查发现漏网:「股票交易异常波动」「扩大产能」→ 已补
   `异常波动|扩产|产能|投产|募投|计提|减值|商誉|担保…` 等词;程序性文件(法律意见书/管理办法/
   独董述职)正确保持噪声。迭代后信号/噪声区分符合人工判断。
3. **DB 层选型**:用 asyncpg(本地/服务器 venv 都有,psycopg2 未装),与 backfill.py 统一。
4. **"连续 3 天无人工"** 无法在研究期直接验证 → 转为部署后观察项(R19 稳定性收口复核)。

**下一步(R4)**:成本闸门。测算日均新闻量 × DeepSeek token 成本,设计两级漏斗(规则粗筛→AI 只看
top N),定死日成本上限(目标 <¥5/日)。这是放量前的预算把关。

## R4 成本闸门(2026-07-15)

**假设**:AI 处理全量新闻太贵,需两级漏斗控成本(<¥5/日)。

**做法**:实测新闻文本体量 → 按 DeepSeek-chat 定价(入¥2/M miss·¥0.5/M hit,出¥8/M,中文保守 1 token/char)算三档成本。

**数据**(实测体量:em_global 单条仅 **125 字**,cctv 583,个股 160):

| 场景 | 机制 | 日成本 | 月成本 |
|------|------|--------|--------|
| A 朴素全量 | AI 读所有新闻+逐股深度 | ¥1.09 | ¥33 |
| B 两级漏斗 | 规则粗筛→AI 精读 topN | ¥0.28 | ¥9 |
| C 漏斗+缓存 | rubric prompt 前缀缓存 | ¥0.17 | ¥5 |

**结论(重要认知修正)**:
1. ❗ **成本不是绑定约束**:A股新闻是短文本,DeepSeek 便宜,连朴素全量都才 ¥33/月。R4 原假设("AI 处理全量太贵")**被证伪**——不需要为省钱牺牲覆盖。
2. 🎯 **真正的约束是 API 速率限制 + 延迟**:90 股逐个调用 = 90 次串行请求,几分钟+可能撞限频。所以漏斗要保留,但**设计理由从"省钱"改为"控吞吐/延迟 + 保质量"**(AI 不该把注意力浪费在噪声上)。
3. **漏斗三层(定稿,吞吐导向)**:
   - **L0 规则粗筛**(0 成本):去重 + 公告白名单(R2)+ 来源优先级 → 砍掉 ~90% 噪声
   - **L1 AI 批量分级**(关键吞吐优化):**一次 prompt 塞 50 条**批量分级,不是逐条调用 → 90 股→几次调用
   - **L2 深度合成**(有界):日报 1 次 + **只对当天有新信号的股票**(~20 只而非 90)提关键词
4. **预算闸门定死**:日成本硬上限 **¥10/日**(宽松,作 runaway-loop 安全阀而非紧优化);正常运行预期 ¥0.2-0.3/日。超限则当日跳过深度合成、只保留规则粗筛日报(降级)。

**下一步(Phase B / R5)**:金融影响分级器——用固定 rubric prompt 做 L1 批量分级(重大/关注/噪声 + 影响方向标签),测同批新闻重复跑的一致性(目标自洽率 >85%)。这是日报和个股跟踪的公共分级层。

### Phase A(R1-R4)地基小结
新闻源已摸清(公告 25 年 PIT 金矿)、时间戳可信(快讯<5min 无前视)、采集管道跑通(0012+collector)、
成本证明不是约束(改为吞吐导向漏斗)。地基完成,进入产品主体 Phase B/C。

## R5 金融影响分级器(2026-07-15)· Phase B 起

**假设**:AI 可稳定把新闻分级(major/watch/noise + 影响维度 + 方向),同批重复自洽率 >85%。

**做法**:固定 rubric prompt(三级 level + 12 类影响维度 dims + 利好/利空/中性 tone),**批量分级**
(一次塞 25 条,R4 吞吐设计);同批重复 3 次测自洽率。news_classify.py。

**数据**:
| 配置 | 三档全一致 | ±1档容差 | major 识别一致 | tone 一致 |
|------|-----------|---------|--------------|-----------|
| temp=0.2 | 56% | — | — | 80% |
| **temp=0** | **100%** | 100% | **100%** | 88% |

**结论**:
1. ✅ **temp=0 是分级层正确配置**:自洽率 56%→100%。分级是**确定性分类任务**,采样随机性(temp>0)只在
   边界模糊档位上放大成假分歧(实测 temp=0.2 的分歧 100% 集中在相邻档 noise↔watch↔major,无极端跳变)。
2. 🎯 **决策相关指标 > 三档全等**:三级本就有序,noise vs watch 决策上差别小,真正关键是 **major 能否
   稳定识别**(推日报头条/触发提醒)。即便边界模糊,major-recall 一致性才是验收标准。
3. 🔍 **L0 聚合洞察(留给 R6)**:快讯常把一个讲话/发布会拆成十几条单句电报(如美联储主席讲话),
   逐句分级既贵又易分歧。日报生成时应在 L0 把"同源+同主题+相近时间"的碎片先聚合再分级。

**下一步(R6)**:每日金融要闻日报——用分级结果生成结构化日报(世界大事/国内大事/市场影响标注/
关联板块),入库 news_digest;处理 R5 遗留的讲话碎片聚合。

## R6 每日金融要闻日报(2026-07-15)

**假设**:用分级结果 + AI 合成能产出信息密度可用、准确的结构化日报。

**做法**:news_daily.py 全流水——L0 规则粗筛+讲话碎片聚合(R5 遗留)→ L1 批量分级(复用 R5,补未分级)→
取 major/watch 前 40 条 → L2 合成结构化日报(综述/世界大事/国内大事/板块影响,每条带对A股影响+方向)→
入库 news_digest(0013)。两级漏斗 L2 段只喂要闻不读全量。

**数据**(实跑 2026-07-14):
- 256 原始 → L0 聚合 239(讲话碎片合并)→ 要闻 40 喂 AI。
- 产出:综述 1 段 + 世界 5 + 国内 5 + 板块 4。
- 质量抽检(人工):CPI 回落/美联储/中东地缘/集成电路出口+96%/近600亿抄底资金 全部抓准;
  板块映射合理(黄金·石油·半导体·军工),方向标注(利好/利空)与常识一致;无编造。

**结论**:
1. ✅ 日报质量可用,信息密度高。两级漏斗有效:全量 256 只有 40 条进 AI,成本/延迟可控。
2. ✅ L0 讲话碎片聚合(SPEAKER_PREFIX 正则)生效:256→239,同发言人连续单句合并,避免 R5 发现的
   逐句分歧问题。
3. **产品化就绪**:news_digest 表可直接供前端「今日要闻」页(R13/R14 或独立页)。
4. 遗留:overview 偶尔把"美联储鹰派"与"CPI回落利好"并列(信息本身矛盾,非模型错),属新闻现实,可接受。

**下一步(R7)**:大事日历——可预知事件(FOMC/CPI/政治局会议/数据发布)比突发更有前瞻价值。

   把这些业绩预告从宏观流里认领到个股——既服务 Phase C 关联,又是 L3 回测金矿。

## R25 对抗稳健性 + 完整性 critic(2026-07-15)· 决定性修正

**假设/做法**:严格 PIT 复查(信号=两事件都已知的较晚日,之后进场)+ 参数扰动 + 子样本 + critic。

**结论(重大修正)**:

3. ✅ **completeness critic 起作用**:正是这轮的 PIT 复查拦下了一个带前视的策略。这是研究纪律的核心价值。
4. **诚实的最终图景向 SAFNA-A 悲观基调收敛**:严格 PIT + 真实摩擦后,**无强可交易新闻 alpha**。

| 龙虎榜净卖出 | 稳健利空(中位≈均值走弱,PIT干净)(R16/17) | 持有者**回避/退出**风险旗 |
| 事件存在性 | 前向波动45% vs 35%(R19) | **波动预警**旗 |
| 全球传导 lead/lag | 对口板块相关强、隔夜先行验真(R18) | **情境解释**(为什么涨跌) |

### 核心教训(与 SAFNA-A 一脉)
1. **A股新闻无强可交易 alpha**:严格 PIT + 真实摩擦后,看似的边际几乎全蒸发或是前视/右尾/小盘幻象。
   本研究 4 次在不同层面撞到 SAFNA-A 的"松关联=噪声、信号计入可交易性即消失"。
2. **新闻的真实价值在信息层(L1/L2)与风险层**,不在信号层(L3)。这**确认了 news_lab 的分层设计**:
   L1/L2 已交付确定价值(日报/关联/关键词/传导解释),L3 诚实归零——**证伪本身是最重要的产出**。
3. **方法论胜利**:中位数(R17)、真实摩擦(R22)、前视复查(R25)三次拦下"看着能赚实则不能"的伪发现。
   没有这些对抗检验,会上线一个带前视的策略。

**下一步(R27)**:产品化——把【活】的信号以 L1/L2/风险方式并入 sentinel(不做可交易腿),
诚实标注"关注/风险提示,非 alpha";文档收口。
