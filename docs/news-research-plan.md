# Sentinel 新闻系统 — 20 轮研究规划(news_lab)

## 已锁定决策(2026-07-14)
1. **先做 A股**(akshare 生态成熟、中文、与当前 A股工作衔接);方法论跑通后再复制到美股。
2. **L3 信号探索保留但放最后**(R15-R20):L1/L2 先拿确定价值,L3 允许全灭,证伪写进 PROGRESS。
3. **AI 预算:两级漏斗 + 严格上限**:规则/白名单粗筛 → AI 只精读 top N;R4 定死日成本上限(目标 < ¥5/日),宁可牺牲部分覆盖也要可持续。

## 追加决策(2026-07-15):全球新闻维度
即便做 A股,也要纳入国外新闻渠道——行业性/地域性/政治性/气候性因素常是全球传导,且对 A股有**提前或滞后**。
- **一手英文源**:GDELT(全球事件库,免费,需 User-Agent + 6s 节流;带来源国/时间戳)构成 lead-time
  (海外英文先发 → 中文转述有时滞)。中文全球快讯(em/sina/ths global,已在用)是二手补充。
- **传导映射(核心)**:维护"全球主题 → A股板块 + 典型提前/滞后天数 + 机制"表(R12),把 lead/lag 显式建模。
- 例:美联储决议(海外隔夜→A股次日经北向,LEAD);芯片管制(政策→国产替代,LEAD);干旱(气候→
  作物→价格,LAG 数周);铜价(全球大宗,近同步);中东冲突(隔夜→石油/军工/黄金次日,LEAD)。


> 目标:给 Sentinel 加一个「每日新闻策略」——像股票策略一样每天自动运转:
> ① 收集世界/国内大事,突出对金融有影响的;② 对推荐/持仓股做关联新闻跟踪(公司/行业/
> 领域/关联方),累计分析挑出关键新闻与关键词;③ 其他对金融有关联的内容。
>
> 方法论沿用 safna_jr:每轮 = 假设 → 验证 → 结论(证伪也是产出),沉淀 PROGRESS.md。
> 铁律不变:无前视(PIT:新闻只能用发布时刻已知的)、诚实定位、数值交叉核验、不吹 alpha。

## 定位分层(整个规划的骨架)

| 层 | 内容 | 价值判定 | 预期 |
|----|------|---------|------|
| **L1 信息层** | 每日金融要闻日报、个股关联新闻流 | 用户看得懂"发生了什么、与我何干"即成立,无需回测 | ✅ 确定落地 |
| **L2 解释层** | AI 讲解/掉出分析/背调引用真实新闻,解释有据 | 解释质量提升(引用可核实) | ✅ 确定落地 |
| **L3 信号层** | 新闻情绪/事件能否改进择时/选股 | safna 级严格回测(PIT、vs 基线、幸存者标注) | ⚠️ 大概率证伪(SAFNA-A 另类数据 10 轮教训),证伪本身是产出 |

**先 L1→L2 拿到确定价值,L3 放最后且允许全灭。**

## 关联维度清单(第②点"帮你想"的部分,R6 起逐步验证覆盖率)

- **公司自身**:公告(巨潮/交易所)、业绩预告与快报、高管/实控人变动、回购增减持、股权质押、诉讼仲裁、监管处罚/问询函、中标合同
- **资金行为**:龙虎榜、大宗交易、北向资金异动(A股);机构 13F 变动(美股,滞后仅作背景)
- **行业/板块**:所属申万行业与东财概念板块的新闻聚合;同行业竞争对手的重大事件(替代/映射效应)
- **供应链**:上游原材料价格(铜/锂/油/运费…按公司主营映射)、下游大客户动态
- **政策/宏观**:部委发文、央行操作、财政/产业政策;利率、汇率(出口占比高的公司)、关税
- **地缘/全球**:海外收入占比高的公司 ↔ 相关国家事件;美股 ↔ FOMC/CPI/就业等日历事件
- **人与舆情**:董事长/实控人个人新闻;股吧/雪球热度突变(只做"异常提醒",不做情绪信号——SAFNA-A 已证伪其独立性)

## Phase A 数据源侦察与管道(R1-R4)——地基

- **R1 新闻源普查(免费/可自动化/PIT 可行)**
  假设:仅用免费源即可覆盖 80% 需求。逐源验证:akshare(财联社电报、东财个股新闻、
  新浪滚动、央视)、GDELT(全球事件库,15min 更新)、交易所/巨潮公告接口、部委 RSS、
  yfinance news(美股)。判定:每源记录 可用性/延迟/历史回补能力/字段/限频,产出源清单表。
- **R2 PIT 时间戳审计**
  假设:各源的"发布时间"可信可用于事后回测。抽样核对(源时间 vs 实际可抓到时间),
  标定每源的"可用时刻=发布+延迟"。判定:延迟>1天或时间戳不可信的源,只进 L1 不进 L3。
- **R3 采集管道原型**
  news_collector.py:定时抓取→去重(标题+URL 指纹)→PG 落库(news_items:source, url,
  title, body, published_at, fetched_at, market_tags, raw)。判定:连续 3 天无人工干预跑通,
  日均条数/重复率达标。
- **R4 成本与吞吐**
  假设:DeepSeek 处理全量新闻太贵,需两级漏斗(规则粗筛→AI 精筛)。测算:日均新闻量×
  token 成本;设计关键词/来源白名单粗筛,AI 只看粗筛后 top N。判定:日成本 < ¥X(定预算)。

## Phase B 每日大事策略(R5-R8)——你的第①点

- **R5 金融影响分级器**
  假设:AI 可稳定地把新闻分级(重大/值得关注/噪声)+ 影响方向标签(利率/汇率/行业/风险偏好)。
  用固定 rubric prompt,对同批新闻重复跑 3 次测一致性。判定:分级自洽率 > 85%,否则改规则化+AI 混合。
- **R6 每日日报生成(产品雏形)**
  news_daily.py:昨日全量→漏斗→「今日金融要闻」结构化日报(世界大事/国内大事/市场影响
  标注/关联板块),入库 news_digest 表。判定:连续 5 天人工评审,信息密度与准确性可用。
- **R7 大事日历(前瞻)**
  假设:可预知事件(FOMC/CPI/政治局会议/数据发布)比突发新闻对用户更有用。建 event_calendar
  表+采集;日报头部带"未来一周日历"。判定:覆盖主要日历事件 90%+。
- **R8 回补历史与查询接口**
  回补 6-12 个月历史要闻(GDELT+财联社可回补),/api/news/digest?date=。为 L3 回测备料。

## Phase C 个股关联跟踪(R9-R14)——你的第②点

- **R9 实体链接 v1(直接匹配)**
  假设:公司名/简称/代码直接匹配可覆盖大部分个股新闻。用 universe.csv 别名表(全称/简称/
  曾用名)匹配新闻,建 stock_news(ticker, news_id, relation_type, confidence)。
  判定:抽 100 条人工核验,准确率>90%,漏报率记录。
- **R10 实体链接 v2(行业/概念/供应链)**
  给每只推荐股建"关联画像":申万行业、东财概念板块、主营关键词(从背调/财报 AI 抽取)、
  上游商品映射表(手工种子+AI 扩展)。新闻→画像匹配打 relation_type(company/industry/
  concept/supply/macro)。判定:推荐股平均每周关联新闻 ≥3 条且相关性人工评审>80%。
- **R11 累计关联分析与关键词**
  假设:滚动 30 天的个股新闻聚类能提炼"当前叙事关键词"(如某股=「机器人+出口+涨价」)。
  AI 对每股新闻集合做主题抽取,存 stock_keywords(ticker, keyword, weight, asof)。
  判定:关键词与人工阅读结论一致性>80%;每日增量更新成本可控。
- **R12 新闻异动检测**
  假设:个股新闻"量的突变"(今天条数 vs 30 天均值)比内容情绪更可靠(SAFNA-A 教训:情绪
  信号不独立,但"有事发生"的提示对人有用)。判定:异动日与该股当日成交量/波动异动重合率,
  仅作 L1 提醒不作信号。
- **R13 详情页新闻 tab + 掉出分析引用新闻**
  产品化:详情页「相关新闻」tab(按 relation_type 分组,关键词云);掉出分析/AI 讲解 prompt
  注入近 7 天关联新闻摘要——解释从"推断"升级为"有据"。判定:掉出分析引用新闻后的人工评审质量。
- **R14 推荐列表新闻标记**
  列表页每行加"📰 n"角标(近 3 天关联新闻数,异动高亮),点击直达新闻 tab。

## Phase D 验证与信号探索(R15-R20)——诚实的最后一段

- **R15 日报影响标注的事后检验**
  R5 分级为"重大"的新闻,事后 T+1/T+5 对应板块/指数的实际波动 vs "噪声"组。
  判定:分级器是否真能区分影响(不是方向,是波动量级)。不能→回炉 rubric。
- **R16 公告事件的 PEAD 复检(站在已有肩膀上)**
  rev+PEAD 是 SAFNA-A 唯一成活事件腿。用新闻管道的公告流复刻它,核对与现有 alt 数据一致性;
  尝试补充事件类型(中标/回购)做同框架检验。判定:与已验证结论数值对得上;新增事件类型
  大概率不独立(允许证伪)。
- **R17 新闻情绪→个股短期方向(预期证伪)**
  严格 PIT 回测:AI 情绪分 vs T+1/T+5 收益,市值中性化后看 IC。判定:诚实记录,
  与 SAFNA-A 结论对照。证伪→写进 PROGRESS 关门,不留幻想。
- **R18 大事→市场级风险灯增强(预期部分证伪)**
  假设:重大风险事件(如政策急转)可作为 A股市场级 Gate 的补充触发器。事件日历+突发分级
  vs Gate 切换的提前性/误报率。判定:能否在不增加误报的前提下提前 1 天以上;不能→只做展示。
- **R19 成本/稳定性收口**
  管道 30 天稳定性复盘:抓取失败率、AI 成本曲线、库容增长;降级策略(AI 挂了→纯规则日报)。
- **R20 总结与产品化收口**
  PROGRESS.md 总结 20 轮结论(活/死清单);news 域并入 sentinel 主服务(调度器每日跑
  news_collector+news_daily);文档+部署。

## 架构草图(实施时细化)

```
engine/news/                     PG 表
  news_collector.py  ──────────▶ news_items(source,url,title,body,published_at,fetched_at,tags)
  news_daily.py(日报策略)──────▶ news_digest(date,digest jsonb)
  news_link.py(实体链接)───────▶ stock_news(ticker,news_id,relation,confidence)
  news_keywords.py(累计分析)───▶ stock_keywords(ticker,keyword,weight,asof)
                                  event_calendar(date,event,importance)
Go: /api/news/digest /api/news/stock?ticker= /api/news/calendar
前端: 「今日要闻」页 + 详情页「相关新闻」tab + 列表📰角标
调度: scheduler 每日 news 域任务(与行情刷新错峰)
```

## 节奏建议

- R1-R4 地基约 1-2 天/轮;R5-R14 是产品主体,每轮见得到界面变化;R15-R20 是验证收口。
- 每轮结束写 PROGRESS.md(假设/做法/数据/结论/下一步),证伪照写——这是 safna 方法论的灵魂。
- 预算闸门放 R4:先算清 AI 成本再放量,避免管道跑起来才发现烧钱。
